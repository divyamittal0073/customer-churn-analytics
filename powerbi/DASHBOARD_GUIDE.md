# Power BI Dashboard — Build Guide

This guide walks you through turning `outputs/powerbi_dataset.csv` (and the
optional `outputs/segment_summary.csv`) into the interactive dashboard.

> A `.pbix` file can't be generated from code — Power BI Desktop owns that
> binary format. This guide reproduces the exact dashboard in ~15 minutes.

---

## 1. Load the data

1. Open **Power BI Desktop** → **Get Data** → **Text/CSV**.
2. Import both:
   - `outputs/powerbi_dataset.csv` (one row per customer — the main fact table)
   - `outputs/segment_summary.csv` (one row per segment — optional, for a quick KPI page)
3. In **Power Query Editor**, confirm data types:
   - `signup_date` → Date
   - `churn_probability` → Decimal Number
   - `risk_tier`, `segment`, `customer_value_tier`, `recommended_action` → Text
   - `churned` → Whole Number (used as a 0/1 flag)
4. Click **Close & Apply**.

---

## 2. Add DAX measures

Create a new table named `_Measures` (Modeling → New Table → `_Measures = {}` is fine,
just used as a home for the measures below), then add these:

```DAX
Total Customers = COUNTROWS(powerbi_dataset)

High Risk Customers =
CALCULATE(COUNTROWS(powerbi_dataset), powerbi_dataset[risk_tier] = "High")

Churn Rate (Historical) =
DIVIDE(
    CALCULATE(COUNTROWS(powerbi_dataset), powerbi_dataset[churned] = 1),
    [Total Customers]
)

Avg Churn Probability =
AVERAGE(powerbi_dataset[churn_probability])

Total Revenue at Risk =
CALCULATE(
    SUM(powerbi_dataset[monetary]),
    powerbi_dataset[risk_tier] = "High"
)

% High Value At Risk =
DIVIDE(
    CALCULATE(
        COUNTROWS(powerbi_dataset),
        powerbi_dataset[risk_tier] = "High",
        powerbi_dataset[customer_value_tier] IN {"Gold", "Platinum"}
    ),
    [High Risk Customers]
)

Avg Customer Lifetime Value =
AVERAGE(powerbi_dataset[monetary])
```

## 3. Build the pages

### Page 1 — Executive Overview
| Visual | Fields |
|---|---|
| KPI Cards | `Total Customers`, `High Risk Customers`, `Churn Rate (Historical)`, `Total Revenue at Risk` |
| Donut chart | `segment` (legend) × `Total Customers` (values) |
| Bar chart | `risk_tier` (axis) × count of customers, colored Red/Amber/Green |
| Line chart | `signup_date` (month) × count of customers — acquisition trend |

### Page 2 — Segmentation Deep Dive (RFM)
| Visual | Fields |
|---|---|
| Matrix | Rows: `segment`; Values: count, `avg_monetary`, `Avg Churn Probability` |
| Scatter chart | X: `recency_days`, Y: `frequency`, Size: `monetary`, Legend: `segment` |
| Table | `customer_value_tier` × `segment` (cross-tab of counts) |

### Page 3 — Churn Risk & Retention Actions
| Visual | Fields |
|---|---|
| Table | `customer_id`, `segment`, `churn_probability`, `risk_tier`, `recommended_action` — sorted descending by `churn_probability`, filtered to `risk_tier = High` |
| Bar chart | `recommended_action` (axis) × count of customers |
| Gauge | `Avg Churn Probability` against a 0.5 target |
| Slicers | `segment`, `region`, `acquisition_channel`, `risk_tier` |

### Page 4 — Model Performance (for stakeholders / technical audience)
Import the two static images generated by the pipeline as picture visuals:
- `outputs/confusion_matrix.png`
- `outputs/roc_curve.png`

Add a table sourced from `outputs/feature_importance.csv` to show which
signals drive the model's predictions (e.g. app logins, purchase frequency,
tenure) — this is the story you tell business stakeholders about *why* the
model flags a customer as at-risk.

---

## 4. Formatting tips
- Color rule of thumb: **Green = Low risk, Amber = Medium, Red = High** — apply
  this consistently across every visual using conditional formatting on `risk_tier`.
- Pin the KPI cards row across all pages using a bookmark or a shared "header" visual group.
- Add a **Segment** slicer synced across all pages (Format → Edit Interactions) so
  a click on "At Risk" on Page 1 filters Page 3's action table too.

## 5. Refreshing with new data
Re-run `python src/pipeline.py` any time you want to regenerate the dataset
(or point the pipeline at real transactional data — see the main README for
how to swap in your own data source), then hit **Refresh** in Power BI.
